# bytetobyte.dev

Откройте `dist/index.html` в браузере или запустите локальный сервер:

```sh
node build.mjs
python -m http.server 8767 --bind 127.0.0.1 --directory dist
```

Адрес: http://127.0.0.1:8767/. Для сборки нужен Node.js 22+. Установка зависимостей не требуется.

## Заявки в каталог

Кнопка «Добавить проект» ведёт в форму GitHub Issue. Автор заполняет метаданные и ссылки прямо на GitHub.

Владелец репозитория проверяет заявку и ставит метку `accepted`. Actions проверяет поля и дубли в каталоге и ожидающих PR, прогоняет сборку и открывает PR из отдельной ветки. Повторное принятие не создаёт второй PR. После ручного слияния GitHub закроет связанный issue.

Для служебного аккаунта включите в Settings → Actions → General параметр Allow GitHub Actions to create and approve pull requests. Разрешение на запись задаётся только в workflow обработки заявок. GitHub может запросить ручное разрешение на запуск PR-проверок; этот workflow уже выполняет сборку до создания PR.

## Языки и CI

Добавьте словарь в `data/locales.json` с тегом BCP 47, названием на языке перевода, набором строк как у `en` и при необходимости с `"dir": "rtl"`. Пункт выбора появится сам. Язык и цветовая тема запоминаются в браузере. Палитры в data/themes.json основаны на встроенных цветовых темах VS Code 1.146.0 и Dracula. Для каждого набора указан источник. VS Code в браузере не требуется.

GitHub Actions строит `dist/index.html` в PR и в `main`, затем сохраняет его как артефакт. Локальная сборка ссылается на pavel-voronin/bytetobyte. GitHub Actions подставляет текущий репозиторий через `CATALOG_REPOSITORY`. Успешная сборка main обновляет HTML в GitHub Release catalog-production. Таймер на Caddy-сервере проверяет метку ревизии и атомарно заменяет страницу. Сервис и таймер находятся в deploy/.
